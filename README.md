# DSH для 1С — сборка для GitHub Pages

Сайт готов к загрузке. Папка site содержит обычные HTML, CSS, JavaScript и изображения. Устанавливать Node.js и собирать сайт для публикации не требуется.

## Публикация через GitHub Actions

1. Создайте репозиторий на GitHub. Для GitHub Free используйте публичный репозиторий.
2. Распакуйте архив и загрузите его СОДЕРЖИМОЕ в корень репозитория, включая скрытую папку .github. Не загружайте сам ZIP. Структура должна быть такой:
   - .github/workflows/pages.yml
   - site/index.html
   - site/styles.css
   - site/config.js
   - site/tracking.js
   - site/images/
   - counter/
   - README.md
3. Используйте ветку main. Если ветка называется иначе, измените branches в .github/workflows/pages.yml.
4. В репозитории откройте Settings → Pages → Build and deployment → Source → GitHub Actions.
5. Откройте Actions → Deploy GitHub Pages → Run workflow. При последующих изменениях в main публикация запускается автоматически.
6. После успешного запуска ссылка будет в Settings → Pages и в результате workflow.

Сайт работает и на адресе username.github.io, и в подпапке username.github.io/repository/. Пути к изображениям и стилям относительные. Workflow публикует только папку site; код счётчика и инструкции не попадают на сайт.

Если загружаете файлы через веб-интерфейс, проверьте, что .github/workflows/pages.yml тоже появился в репозитории. Включите показ скрытых файлов в проводнике при необходимости.

## Альтернатива: публикация из ветки

Скопируйте СОДЕРЖИМОЕ папки site в корень отдельного репозитория. В Settings → Pages выберите Deploy from a branch → main → /(root). Файл .nojekyll должен присутствовать. В этом варианте workflow не нужен.

## Счётчик переходов — важно

GitHub Pages обслуживает статические файлы и не запускает серверную базу данных. Поэтому исходный серверный счётчик нельзя просто перенести внутрь Pages.

В сборку включён отдельный Cloudflare Worker с базой D1. Он подготовлен, но НЕ развёрнут и НЕ подключён к сайту. До подключения кнопки «Инструкция» работают напрямую и переходы не записываются.

### Подключение счётчика

Требуются аккаунт Cloudflare, Node.js и npm. В терминале откройте папку counter.

1. Авторизуйтесь:
   npx wrangler@4.92.0 login
2. Создайте базу:
   npx wrangler@4.92.0 d1 create dsh-instruction-clicks
3. В counter/wrangler.toml замените REPLACE_WITH_DATABASE_ID на выданный database_id.
4. В PAGE_ORIGIN укажите адрес вашего сайта БЕЗ пути и завершающего слеша: https://YOUR-USERNAME.github.io. Для собственного домена укажите его origin, например https://example.com.
5. Примените схему ОДИН раз:
   npx wrangler@4.92.0 d1 execute dsh-instruction-clicks --remote --file schema.sql
6. Опубликуйте счётчик:
   npx wrangler@4.92.0 deploy
7. Скопируйте адрес Worker из результата. В site/config.js задайте:
   window.DSH_COUNTER_ENDPOINT = "https://ВАШ-АДРЕС-WORKER/go/instructions";
8. Сохраните изменение в main. GitHub Actions опубликует обновление сайта.
9. Откройте https://ВАШ-АДРЕС-WORKER/api/stats, нажмите «Инструкция» на сайте и снова проверьте статистику: итог должен увеличиться на 1.

Все кнопки «Инструкция» используют общий счётчик. Хранятся дата UTC и количество нажатий; имена, IP-адреса и идентификаторы посетителей приложение не сохраняет. Инфраструктура хостинга может вести собственные журналы.
Повторные нажатия считаются повторно: это не уникальные посетители и не подтверждённые скачивания. Обычные GET-запросы и предпросмотры ссылок счётчик не увеличивают. Это простой счётчик, без защиты от намеренной накрутки.
Статистика по адресу Worker /api/stats публичная. Там нет персональных данных — только общее число и последние 30 дней с переходами.
При ошибке записи в доступном Worker посетитель всё равно попадёт на страницу релиза GitHub, но нажатие не будет учтено. Если сам Worker недоступен, очистите DSH_COUNTER_ENDPOINT для возврата к прямой ссылке.
Новая база начинает считать с нуля; локальная тестовая статистика в неё не переносится.
Стоимость внешнего сервиса определяется условиями Cloudflare; бесплатность не гарантируется.

## Изменение страницы

- site/index.html — текст и структура страницы.
- site/styles.css — оформление и мобильная адаптация.
- site/images/ — скриншоты.
- site/config.js — адрес внешнего счётчика.
- site/tracking.js — подключение кнопок к счётчику.

Это самостоятельная статическая версия текущего лендинга. Здесь нет зависимости от Sites, React или серверных маршрутов исходного проекта.

## Проверено перед передачей

Генерация из текущего лендинга, локальные ссылки на изображения и стили, отсутствие зависимости от серверных маршрутов, синтаксис JavaScript и логика серверного счётчика. Публикация в вашем GitHub/Cloudflare аккаунте не выполнялась.
